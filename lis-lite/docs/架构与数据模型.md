# 多医院互联 LIS 检验信息系统（精简版）

## 架构

采用模块化单体：标本与条码、项目与收费、HL7仪器接口、质控、结果审核、危急值、报告、转检与审计模块。内存仓储仅用于演示；生产环境应替换为 PostgreSQL，并对机构ID实施行级隔离。

## 数据模型

- 机构/用户/审计：`organization`、`user`、`audit_log`
- 标本链路：`patient`、`test_order`、`specimen`、`specimen_event`
- 主数据：`test_catalog`、`test_price_code`、`reference_range`、`critical_value_rule`
- 仪器质控：`instrument`、`instrument_run_batch`、`qc_record`、`instrument_message`、`test_result`
- 审核报告：`result_review`、`critical_alert`、`critical_alert_signature`、`critical_notification`、`lab_report`
- 双向转检：`organization_relationship`、`referral_order`、`referral_specimen`、`referral_item`、`referral_payload`、`referral_result`

## 强制规则

1. 危急值只要未完成两名不同审核人的初审和复审，即禁止签发。
2. 质控失控时锁定同批、尚未签发的结果和报告；解除需质控员审计留痕。
3. 合作机构仅获取转检号、脱敏令牌、性别、年龄、标本和项目；不得读取姓名、证件、联系方式、地址、就诊号或源院内部患者ID。
4. 所有关键动作记录审计事件；已审核结果应采用版本记录，不能直接覆盖。

## 运行与验收

```bash
npm run 验收
npm start
```

`npm run 验收`覆盖：标本接收/条码、HL7上机、危急值双签、报告HTML（PDF渲染输入）、外送脱敏与回传、质控失控锁定。
